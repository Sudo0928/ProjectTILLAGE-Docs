# ProjectTILLAGE-Docs MVP PRD

> **본 문서**는 사이트의 기본 골격(F001~F014) + **비기획자(아티스트/사운드/외부 개발자/마케터/투자자) 친화 진입 동선** + **기획자의 기존 Notion 작성 패턴을 자동 변환하는 정책**(F015~F019)을 정의합니다. 초기 골격 버전은 `docs/PRD.archive.md`로 보존됩니다.

## 핵심 정보

**목적**: Notion에 작성한 게임 기획서를 별도 작업 없이 자동으로 웹에 게시하되, **비기획자도 5분 안에 게임 컨셉을 파악**할 수 있도록 작성 패턴을 자동 변환·큐레이션하는 발행 사이트
**한 줄 가치 제안**: "기획자는 Notion에서 평소처럼 쓰고, 비기획자는 웹에서 친절하게 읽는다"
**대상 게임**: Project TILLAGE — 포스트 아포칼립스 농사+생존 게임. Logline은 "5년 안에 감염으로 죽을 주인공이 작은 섬에서 농사를 짓고 섬 사람들과 인연을 쌓아 가면서 삶의 의미를 찾아가는 게임"

### 사용자 (2그룹)

#### 그룹 A — 기획자(작성자)

- 1인 또는 소규모 팀의 게임 기획자 본인
- Notion으로 기획서를 작성·관리하고 외부에 공유하기를 원함
- 새 작성 규칙을 강요받기를 원하지 않음 (기존 패턴을 그대로 유지하고 싶음)

#### 그룹 B — 비기획자(이해관계자) — 5개 페르소나로 세분

| 페르소나          | 5초 안에 알고 싶은 것 | 5분 안에 알고 싶은 것       | 가장 답답한 것                            |
| ----------------- | --------------------- | --------------------------- | ----------------------------------------- |
| 아티스트          | 게임 분위기 한 줄     | 비주얼 무드/캐릭터 톤       | 비주얼 자료가 흩어져 있음                 |
| 사운드 디자이너   | 핵심 감정             | 사운드 방향성/금지 요소     | 사운드 페이지가 묻혀 보이지 않음          |
| 외부 프로그래머   | 무슨 게임인지         | 핵심 시스템 1개의 동작 흐름 | `[임시]/[작성 필요]` 상태가 구분되지 않음 |
| 마케터/홍보       | 한 마디 셀링 포인트   | 핵심 셀링 3가지             | 한 줄 카피 위치를 모름                    |
| 외부(투자자/지인) | 한 줄 컨셉 + 분위기   | 5분 개요                    | "어디서부터 봐야 할지" 막막함             |

## 사용자 여정

```
1. 홈 페이지 진입
   ↓ (페이지 로드 시 Notion API 호출)

2. HERO 영역에서 한 줄 Logline + 분위기 5초 파악
   ↓

3. "처음 오셨나요?" 추천 글 3개 또는 "관심사로 골라보기"(페르소나별 큐레이션)에서 분기
   ↓ 사용자 선택

   [A] 추천 글 카드 클릭          → 글 상세 페이지
   [B] 페르소나 큐레이션 클릭     → 글 상세 페이지
   [C] 카테고리 메뉴 클릭         → 카테고리 페이지 → 카드 클릭 → 글 상세 페이지
   [D] 검색어 입력                → 검색 결과 페이지 → 카드 클릭 → 글 상세 페이지
   ↓

4. 글 상세 페이지
   - 본문 상단 TL;DR 박스로 30초 요약 확인
   - 섹션 인트로 강조 박스로 각 섹션 의도 파악
   - [확정]/[임시] 배지로 작업 상태 인지
   - "미결 사항" 섹션은 기본 접힘(읽기 부담 감소)
   - 본문 하단 "연동 문서" 카드로 다음 글 자연 탐색
   ↓

5. 추천 글/연동 문서 클릭 → 다음 글 상세 페이지 (탐색 반복)
   또는 헤더로 돌아가 카테고리/검색 재진입

6. 종료
```

### 페르소나별 진입 시나리오

| 페르소나          | 진입 동선                                 | 핵심 페이지 노출                           |
| ----------------- | ----------------------------------------- | ------------------------------------------ |
| 아티스트          | 홈 → "관심사로 골라보기" → 비주얼/UI 묶음 | 📹 비주얼 기획, 🎨 UI/UX 기획              |
| 사운드 디자이너   | 홈 → "관심사로 골라보기" → 사운드 묶음    | 🎶 사운드 기획, 🎞️ 내러티브 기획           |
| 외부 프로그래머   | 홈 → "처음 오셨나요?" → 핵심 시스템 1개   | 📌 핵심 정의, ⚙️ 시스템 기획, 🛠️ 기술 기획 |
| 마케터/홍보       | 홈 → "관심사로 골라보기" → 마케팅 묶음    | 🛫 방향성 기획, 🪙 수익화 기획             |
| 외부(투자자/지인) | 홈 → "처음 오셨나요?" → 5분 개요 글       | 📌 핵심 정의, 📹 비주얼 기획               |

> **노출 정책**: Notion에서 신규 속성 `웹 게시 = 발행됨`인 페이지만 사이트에 노출됩니다. 기존 `상태`(시작 전/진행 중/완료)는 **게임 기획 작업 진행도**일 뿐이며 사이트 노출 여부와 무관합니다.

### 3. 비기획자 친화 신규 기능 (v2 추가)

| ID       | 기능명                     | 설명                                                                                                                                                                                                                                                                                                                                                             | MVP 필수 이유                                                 | 관련 페이지    |
| -------- | -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- | -------------- |
| **F015** | 비기획자 진입 큐레이션     | 홈 상단 HERO + Logline 노출, "처음 오셨나요?" 섹션(`추천 순위` 1~3 글 자동 표시 + 동률 시 `발행일` 내림차순 보조 정렬), "관심사로 골라보기" 섹션(페르소나별 정적 큐레이션 — **5개 페르소나 모두 서로 다른 분류 묶음 보장**)                                                                                                                                      | 비기획자가 "어디서부터 봐야?"를 해결                          | 홈 페이지      |
| **F016** | TL;DR 자동 추출            | 본문 상단에 자동 강조 박스 노출. 우선순위: ① "# 0. 한 줄 정의" 섹션 본문 → ② 페이지 최상단 첫 quote 블록 → ③ Notion `요약` 속성 → ④ 본문 첫 단락 50자 fallback. **각 단계에서 추출 본문이 빈 문자열이거나 `✏️ [작성 필요]`/`[TBD]`/`[작성중]` placeholder 패턴이면 다음 단계로 fall-through**                                                                    | 5초 진입에 필요한 한 줄 컨셉을 작성자 부담 없이 보장          | 글 상세 페이지 |
| **F017** | 작성 패턴 자동 변환        | callout 블록(icon.emoji === '💡')을 파란 배경 인트로 박스로, 표 셀의 `[확정]`/`[임시]` 텍스트를 색상 배지(녹색/노랑)로, "# N. 미결 사항" 섹션을 기본 접힘 토글(🚧 "기획자 작업 중")로 자동 변환                                                                                                                                                                  | 비기획자가 작업 상태를 시각적으로 즉시 인지                   | 글 상세 페이지 |
| **F018** | 연동 문서 → 추천 카드      | 본문 하단 "# N. 연동 문서" 섹션을 자동 감지해 그 안의 페이지 멘션 목록을 카드 그리드로 변환(제목 + 분류 칩 + 요약 1줄). **멘션된 페이지가 `웹 게시 != 발행됨`이면 카드에서 숨김. 노출 가능한 멘션이 0개면 섹션 영역 자체를 숨김**                                                                                                                                | 다음 글 자연 탐색 동선 확보                                   | 글 상세 페이지 |
| **F019** | 읽기 메타 + 동일 분류 추천 | **글 상세 페이지에만 읽기 시간(한국어 분당 500자) 표시**(카드는 본문 fetch 비용을 피하기 위해 노출 제외). 카드/상세 메타에 `독자 수준` 칩 표시(**미설정 글은 칩 미노출**). 본문 하단에 같은 `분류` 글 3개 자동 추천(발행일 내림차순). **현재 페이지 ID 제외는 Notion API의 `does_not_equal` ID 필터 부재로 인해 LIMIT 4 후 서버 컴포넌트에서 클라이언트 후처리** | 비기획자에게 분량과 난이도를 미리 알리고, 끊김 없는 탐색 제공 | 글 상세 페이지 |

### 4. MVP 이후 기능 (제외)

- 회원가입/로그인 등 인증 기능 (사이트는 공개 읽기 전용)
- 댓글, 좋아요, 북마크, 질문 등 사용자 상호작용
- 다크모드/폰트 크기 조절 등 사용자 설정 (시스템 테마 토글 수준만 유지)
- 글 작성/편집 UI (작성은 Notion에서만)
- 다국어 지원, RSS, 사이트맵 자동화
- 조회수/방문자 분석 대시보드 (Vercel Analytics 정도만 활용)
- **용어 사전(Glossary)** — 전용 페이지 + 본문 자동 링킹 (비기획자가 가장 부담을 느끼는 부분이지만 MVP 범위 초과)
- **페이지 멘션 인라인 미니카드** — 본문 안 페이지 멘션을 호버 시 미리보기 카드로 변환 (F018에서 하단 카드 그리드로만 처리, 인라인은 후순위)
- **페르소나 코스 동적화** — 별도 큐레이션 DB로 페르소나별 추천 글 시퀀스를 운영 (MVP는 정적 분류 매핑)
- **추천 알고리즘** — 태그 유사도/조회 기반 추천 (MVP는 같은 분류 단순 정렬)
- **본문 인라인 페이지 멘션 호버 미리보기** — 작성자가 멘션 시 카드 자동 노출 (F018 후속)

## 작성 패턴 변환 규칙

> 기획자(님)가 이미 일관되게 사용 중인 작성 패턴을 사이트 측 변환 로직이 인식해 자동 변환합니다. 작성자에게 새 규칙을 강요하지 않습니다.

| 입력 패턴 (Notion 본문)           | 의미                      | 사이트 변환 결과                                      | 관련 기능  |
| --------------------------------- | ------------------------- | ----------------------------------------------------- | ---------- |
| 페이지 최상단 첫 `> 인용/quote`   | 설계 원칙 또는 한 줄 메타 | TL;DR 강조 박스 (본문 상단 고정)                      | F016       |
| `# 0. 한 줄 정의` 섹션            | 명시적 한 줄 요약 자리    | TL;DR 박스 (최우선 소스)                              | F016       |
| `> 💡 ~` 섹션 callout             | 섹션 메타 설명            | 섹션 인트로 강조 박스 (파란 배경)                     | F017       |
| 표 셀의 `[확정]` 텍스트           | 확정 마킹                 | 녹색 배지                                             | F017       |

| `# N. 연동 문서` 섹션             | 페이지 멘션 리스트        | 하단 추천 글 카드 그리드                              | F018       |
| 본문 안 페이지 멘션               | 다른 문서 참조            | 인라인 미니카드(MVP 후순위 — 텍스트 링크로 우선 처리) | (MVP 이후) |

| Notion 콜아웃 블록 (💡 외 이모지) | 일반 강조                 | 일반 callout 스타일(아이콘 + 배경)                    | F002       |

### TL;DR 자동 추출 우선순위 (F016)

```
1. "# 0. 한 줄 정의" 섹션이 존재하면 → 그 섹션의 첫 단락 본문을 TL;DR로 사용
2. 위가 없고 페이지 최상단 첫 블록의 type === 'quote'이면 → quote 텍스트를 TL;DR로 사용
3. 위가 모두 없고 Notion `요약` 속성이 비어있지 않으면 → 요약 속성을 TL;DR로 사용
4. 위가 모두 없으면 → 본문 첫 단락의 앞 50자를 fallback으로 사용 (말줄임 처리)

각 단계에서 추출 본문이 빈 문자열이거나 `✏️ [작성 필요]`/`[TBD]`/`[작성중]` 같은 placeholder 패턴이면
해당 단계를 건너뛰고 다음 단계로 fall-through.
placeholder 정규식 후보: /^\s*(✏️\s*)?\[\s*(작성\s*필요|TBD|작성중|미작성|작성중입니다?)\s*\]\s*$/
```

### 읽기 시간 계산 (F019)

- 한국어 분당 500자 기준
- 본문 블록을 평문으로 펼쳐 글자 수 집계 → `Math.max(1, Math.round(글자수 / 500))` 분
- 카드/상세 메타에 "약 N분" 형식으로 표시

## 비기능 요구사항

- **성능 캐시**: Notion API 호출 비용을 줄이기 위해 Next.js `revalidate = 60` ISR로 목록/상세 캐시. **F018 멘션된 페이지의 메타(제목/분류/요약)는 빌드 단위로 `unstable_cache` 또는 React 19 `cache()`로 메모이즈하여 N+1 fetch + Notion 평균 3 req/s rate limit burst 방지**
- **렌더링 전략**: 글 목록(홈/카테고리 인덱스/카테고리 상세)과 상세는 서버 컴포넌트 + ISR, **검색만 `dynamic = 'force-dynamic'`로 동적 처리**
- **컨테이너 강제**: 모든 페이지 상위 래퍼는 공통 `Container` 컴포넌트 사용 (shrimp-rules.md 제약 준수)
- **접근성**: 시맨틱 마크업(`header`/`main`/`nav`/`article`), 명도 대비 4.5:1 이상, 키보드 포커스 스타일 유지, 검색 입력/카테고리 메뉴 `aria-*` 정리
- **가독성**: 본문은 `@tailwindcss/typography` 기반 `prose` 적용, 모바일에서 16px 이상 본문 폰트
- **에러 안전성**: Notion API 실패 시 사용자에게 친절한 안내 + 콘솔 로깅, 크래시 방지. 미지원 블록은 안전한 fallback
- **보안**: `NOTION_TOKEN`은 서버 전용 모듈에서만 사용. 클라이언트 번들에 절대 노출 금지. `.env.local`은 커밋 금지(`.env.local.example`만 동기화)
- **한국어 UI**: 모든 사용자 노출 문자열은 한국어. 영문 식별자(타입/변수)와 분리

### v1 → v2 차이 검증

- v1의 모든 기능(F001~F014)은 v2에서 그대로 유지됨
- v2 신규(F015~F019)는 모두 페이지별 상세 기능 표 + 메뉴 구조 + 정합성 검증 1단계에 빠짐없이 반영됨
