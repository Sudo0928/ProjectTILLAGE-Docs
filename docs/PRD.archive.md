# ProjectTILLAGE-Docs MVP PRD

## 핵심 정보

**목적**: Notion에 작성한 기획서를 별도 작업 없이 자동으로 웹에 게시하는 Notion 기반 문서 발행 사이트
**사용자**: 기획서/문서를 Notion으로 관리하고 외부에 공유하고 싶은 1인 기획자/개발자 및 비기획자 동료/이해관계자

---

## 사용자 여정

```
1. 홈 페이지 진입
   ↓ (페이지 로드 시 Notion API 호출)

2. 최근 발행된 기획서 카드 목록 확인
   ↓ 사용자 선택 분기

   [A] 카드 클릭          → 글 상세 페이지 → 본문 읽기
   [B] 카테고리 메뉴 클릭  → 카테고리 페이지 → 카드 클릭 → 글 상세 페이지
   [C] 검색어 입력         → 검색 결과 페이지 → 카드 클릭 → 글 상세 페이지
   ↓

3. 글 상세 페이지에서 본문 정독
   ↓ 사용자 다음 액션

   [A] 같은 카테고리 글 더 보기 → 카테고리 페이지
   [B] 홈으로 돌아가기           → 홈 페이지
   [C] 다른 글 검색              → 검색 결과 페이지

4. 종료 또는 다른 글 탐색 반복
```

> Notion에서 Status가 "발행됨"인 페이지만 사이트에 노출되며, "초안"은 자동으로 숨겨집니다.

## 데이터 모델

> 데이터 저장소는 Notion이며, 애플리케이션은 Notion API 응답을 정규화한 타입으로 사용합니다.

### Post (Notion 데이터베이스 페이지 정규화)

| 필드        | 설명             | 타입/관계                          |
| ----------- | ---------------- | ---------------------------------- |
| id          | Notion 페이지 ID | string (UUID)                      |
| title       | 기획서 제목      | string (Notion title)              |
| category    | 단일 카테고리    | string (Notion select)             |
| tags        | 태그 목록        | string[] (Notion multi_select)     |
| publishedAt | 발행일           | ISO Date (Notion date)             |
| status      | 발행 상태        | "발행됨" \| "초안" (Notion select) |
| slug        | URL용 식별자     | string (id 기반 자동 생성)         |

### PostContent (글 상세 본문)

| 필드         | 설명                   | 타입/관계      |
| ------------ | ---------------------- | -------------- |
| postId       | 연결되는 Post ID       | → Post.id      |
| blocks       | Notion 블록 배열       | NotionBlock[]  |
| coverImage   | 커버 이미지 URL (선택) | string \| null |
| lastEditedAt | 마지막 편집 시각       | ISO Date       |

### Category (목록/필터용 파생 모델)

| 필드      | 설명                | 타입/관계          |
| --------- | ------------------- | ------------------ |
| name      | 카테고리명          | string             |
| slug      | URL용 식별자        | string (name 기반) |
| postCount | 해당 카테고리 글 수 | number             |

## 비기능 요구사항

- **성능 캐시**: Notion API 호출 비용을 줄이기 위해 Next.js `revalidate`(예: 60초 ISR)로 목록/상세 캐시
- **렌더링 전략**: 글 목록과 상세는 서버 컴포넌트 + ISR, 검색은 서버 액션 또는 라우트 핸들러로 동적 처리
- **접근성**: 시맨틱 마크업, 명도 대비 4.5:1 이상, 키보드 포커스 스타일 유지
- **가독성**: 본문은 `@tailwindcss/typography` 기반 `prose` 적용, 모바일에서 16px 이상 본문 폰트
- **에러 안전성**: Notion API 실패 시 사용자에게 친절한 안내 + 콘솔 로깅, 크래시 방지

## 성공 지표 (1인 개발자용 가벼운 기준)

- Notion에 발행됨 상태로 글을 등록한 뒤 60초 이내 사이트 반영
- 모바일/데스크톱에서 Lighthouse Performance 85점 이상
- 핵심 동선(홈 → 상세, 카테고리 → 상세, 검색 → 상세) 전부 무오류 동작
- 외부 공유 시 링크 미리보기에 제목/요약이 정상 표시

## 기술 스택 (최신 버전)

### 프론트엔드 프레임워크

- **Next.js 15.5.3** (App Router + Turbopack) — 서버 컴포넌트, ISR, 메타데이터 API 활용
- **React 19.1.0** — 최신 동시성 기능 및 서버 컴포넌트 활용
- **TypeScript 5** — 정적 타입 안전성 확보

### 스타일링 및 UI

- **TailwindCSS v4** — 설정 파일 없는 새로운 엔진
- **shadcn/ui** (new-york style) — Card, Badge, Input, Button, Skeleton 등 활용
- **@tailwindcss/typography** — Notion 본문 가독성 향상용 prose 스타일
- **Lucide React** — 검색/카테고리/태그 아이콘

### Notion 연동

- **@notionhq/client** — Notion 공식 SDK
- **notion-to-md** 또는 자체 블록 매핑 유틸 — Notion 블록 → HTML 변환

- **React Hook Form 7.x** — 검색 입력 등 폼 상태 관리

## 정합성 검증 결과

- 기능 명세의 모든 ID(F001–F004, F010–F014)가 페이지별 상세 기능 또는 헤더에서 구현됨
- 메뉴 구조의 모든 항목(홈/카테고리/검색 결과/글 상세/푸터)이 페이지별 상세 기능에 1:1 대응됨
- 페이지별 상세 기능에 사용된 모든 기능 ID가 기능 명세에 정의되어 있음
- 고아 메뉴/기능 없음, 누락 페이지 없음
